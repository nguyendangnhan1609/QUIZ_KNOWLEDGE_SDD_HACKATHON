This is the executable task list for Phase 0. Each task is sized to be a single AI prompt or a single ~30-minute block of work.

---

## 1. Phase Overview

### Purpose

Stand up the project skeleton — running Next.js 15 app, locked dependencies, configured tooling, validated env vars, accessible Supabase. Until Phase 0 is green, every later phase is blocked.

### Expected outcome

A developer (or AI assistant) can pull `main`, run `pnpm install && pnpm dev`, and see a styled landing page that boots cleanly with all integrations wired (DB credentials, Storage credentials, OpenAI key — even if not yet exercised). All shadcn primitives needed by Phases 2–7 are pre-installed. The folder layout matches `technical-design.md` §14.

### Why this setup matters for future phases

- **Phase 1** writes the Prisma schema; Prisma must already be installed and configured.
- **Phase 2** uploads files into Supabase Storage; bucket `docs` must exist.
- **Phase 3** calls OpenAI; the API key must already be in `.env.local`.
- **Phase 4–6** consume shadcn primitives; installing them all up-front avoids mid-feature `npx shadcn add` interruptions.
- **Validation tax now = zero rework later.** A misconfigured `DATABASE_URL` discovered in Phase 5 costs 2 hours; the same error caught in Phase 0 costs 5 minutes.

### Task 0.2 — Configure TailwindCSS

**Objective.** Confirm Tailwind v4 is auto-discovering classes from `src/`, lock in the styling strategy, and decide whether to add custom theme tokens before shadcn runs in Task 0.3.

**Technical Requirements (Tailwind v4 reality).**
- Tailwind **v4** comes pre-configured from Task 0.1 — `@tailwindcss/postcss` plugin in `postcss.config.mjs`, `@import "tailwindcss";` in `src/app/globals.css`.
- **No `tailwind.config.ts` is generated by v4.** Content paths are auto-discovered from imports — anything imported from `src/` gets scanned automatically.
- **Do not** add v3 idioms (`@tailwind base; @tailwind components; @tailwind utilities;`, `content: [...]` arrays). They are no-ops or errors in v4.
- Custom theme tokens, if needed, live in an `@theme { … }` block inside `globals.css` — but skip for now and let shadcn (Task 0.3) write its own tokens.
- Folder styling strategy:
  - **Tailwind utilities only** — no inline `style={...}` (except dynamic widths like the analytics bar in Phase 6).
  - **No CSS modules.**
  - **`globals.css` is for the Tailwind import + theme tokens**, not component styles.
  - Component-local styles via `cn()` from `src/lib/utils.ts` (added by shadcn in Task 0.3).
- Detailed guide: see [`task-0-2-configure-tailwindcss.md`](./task-0-2-configure-tailwindcss.md).

**Dependencies.** Task 0.1.

**Acceptance Criteria.**
- `src/app/globals.css` contains exactly `@import "tailwindcss";` (no v3 directives).
- A `bg-blue-500 text-white p-4 rounded` class on a `<h1>` in `src/app/page.tsx` renders styled (re-verifies Task 0.1 §5.2).
- Tailwind IntelliSense works in VS Code (verify via hover) — install the **Tailwind CSS IntelliSense** v0.12+ extension for v4 support.
- No `tailwind.config.ts` file exists at repo root or under `quiz-knowledge/`.

**Validation Steps.**
1. `Get-Content quiz-knowledge/src/app/globals.css` → single `@import` line.
2. `Test-Path quiz-knowledge/tailwind.config.ts` → False.
3. Re-run the §5.2 Tailwind smoke test from Task 0.1 detail guide if not already verified post-cleanup.

**Estimated Complexity.** Low (with v4, this is largely verification — most of the work was done at scaffold time).

**AI Coding Opportunity.** Low. AI helpful only if you need to draft a custom `@theme` block; default path defers to Task 0.3 (shadcn writes theme tokens).

### Task 0.4 — Setup Prisma ORM

**Objective.** Install Prisma, define a placeholder schema (real schema lands in Phase 1), and prove `prisma generate` + the singleton client both type-check.

**Technical Requirements (Prisma 7 reality).**
- Pre-flight: `pnpm approve-builds --all` after installing prisma + @prisma/engines (pnpm 11 build-script gate).
- `pnpm add @prisma/client`
- `pnpm add -D prisma dotenv` — `dotenv` is required because `prisma.config.ts` no longer auto-loads `.env`.
- `pnpm prisma init` — creates `prisma/schema.prisma`, `prisma.config.ts`, and `.env` with a sample managed-Prisma-Postgres URL (replace it).
- Edit `prisma/schema.prisma`:
  - `generator client { provider = "prisma-client-js" }` — the legacy generator. The new v7 default `prisma-client` generator requires `accelerateUrl` or a driver adapter; we want classic URL-based connection.
  - `datasource db { provider = "postgresql" }` — **no `url` or `directUrl` here.** Prisma 7 rejects both.
  - Add a placeholder model:
    ```prisma
    model Health {
      id Int @id @default(autoincrement())
    }
    ```
- Edit `prisma.config.ts`:
  - Keep `import "dotenv/config";`.
  - Set `datasource: { url: process.env["DATABASE_URL"] }`.
  - **Don't add `directUrl`** — not in the type.
- Replace the sample `prisma+postgres://localhost:51213/...` URL in `.env` with traditional Postgres placeholders:
  ```
  DATABASE_URL="postgresql://placeholder:placeholder@localhost:5432/quizdb?schema=public"
  DIRECT_URL="postgresql://placeholder:placeholder@localhost:5432/quizdb?schema=public"
  ```
- Singleton client at `src/lib/db/prisma.ts` importing from `@prisma/client` (NOT `@/generated/prisma/client` — that path only applies to the new generator).
- Detailed step-by-step (commands, validation, pitfalls): see [`task-0-4-setup-prisma.md`](./task-0-4-setup-prisma.md).

**Dependencies.** Task 0.1.

**Acceptance Criteria.**
- `pnpm prisma generate` succeeds.
- `pnpm prisma format` exits 0 with no diff.
- `import { prisma } from '@/lib/db/prisma'` type-checks against a smoke `route.ts`.
- `pnpm-workspace.yaml` `allowBuilds` lists `prisma: true` and `@prisma/engines: true`.

**Validation Steps.**
1. `pnpm prisma generate` → "Generated Prisma Client (v7.8.0) to .\node_modules\.pnpm\…\@prisma\client".
2. Add a temporary `src/app/api/_test/route.ts` that imports `prisma` and returns `Response.json({ ok: true })` — confirm `node node_modules/typescript/bin/tsc --noEmit` exits 0.
3. Delete the temporary file. Clear `.next/`. Re-run `tsc --noEmit` → 0.

**Estimated Complexity.** Medium (Prisma 7 config changes are non-obvious; smooth once known).

**AI Coding Opportunity.** High for the singleton — but **AI prompts written before late-2025 will produce a `directUrl = env(...)` schema that fails on Prisma 7.** Use the detailed guide ([`task-0-4-setup-prisma.md`](./task-0-4-setup-prisma.md)) as the source of truth, not an AI's first draft.

### Task 0.5 — Setup Supabase

**Objective.** Provision a Supabase project, capture all credentials, and pre-create the storage bucket so Phase 2 has nothing to wait on.

**Technical Requirements.**
- Create Supabase project (free tier). Region close to Vercel deployment region.
- From **Project Settings → Database**:
  - Copy the **pooled** connection string (port 6543) → `DATABASE_URL`.
    - Append `?pgbouncer=true&connection_limit=1` if not present.
  - Copy the **direct** connection string (port 5432) → `DIRECT_URL`.
- From **Project Settings → API**:
  - Copy `URL` → `SUPABASE_URL`.
  - Copy `service_role` key → `SUPABASE_SERVICE_ROLE_KEY` (server only, never client).
- From **Storage**:
  - Create bucket `docs`. Public: **No**. RLS: leave default (server uses service role).
- Capture all five values for Task 0.6.

**Dependencies.** None (web UI work; can run parallel to Tasks 0.1–0.4).

**Acceptance Criteria.**
- A Supabase project exists with the bucket `docs`.
- All five credentials are in a temporary local note (will be moved to `.env.local` in Task 0.6).
- The pooled URL has `?pgbouncer=true&connection_limit=1`.

**Validation Steps.**
1. From a local `psql` (or any Postgres client), connect to `DIRECT_URL` → `SELECT version();` returns Postgres 15+.
2. In Supabase Studio → Storage → confirm `docs` bucket exists and is private.

**Estimated Complexity.** Low (web UI; no code).

**AI Coding Opportunity.** None (manual provisioning).

### Task 0.6 — Configure Environment Variables

**Objective.** Wire `.env.local` and add **fail-fast env validation** via `@t3-oss/env-nextjs` so a missing var crashes the boot, not the third request.

**Technical Requirements.**
- `pnpm add @t3-oss/env-nextjs zod`
- Create `.env.local` at repo root with the six keys:
  ```
  DATABASE_URL=...
  DIRECT_URL=...
  OPENAI_API_KEY=...
  SUPABASE_URL=...
  SUPABASE_SERVICE_ROLE_KEY=...
  SUPABASE_STORAGE_BUCKET=docs
  ```
- Add `src/lib/config/env.ts` per `technical-design.md` §13.2.
- Add `.env.local` to `.gitignore` (default in Next.js, but verify).
- Naming convention: server-only vars use plain `UPPER_SNAKE_CASE`. **No `NEXT_PUBLIC_*` in this project** — every secret is server-side.
- Secret handling: `OPENAI_API_KEY` and `SUPABASE_SERVICE_ROLE_KEY` are never imported into a Client Component. The `env` object from `src/lib/config/env.ts` is the only path.

**Dependencies.** Task 0.5 (need the actual values).

**Acceptance Criteria.**
- `pnpm dev` boots successfully with all six values set.
- Removing any one var → boot fails with a Zod error pointing to the missing var.
- `git status` does not show `.env.local`.

**Validation Steps.**
1. Boot succeeds.
2. Comment out `OPENAI_API_KEY` in `.env.local` → boot fails with "OPENAI_API_KEY: required".
3. Restore the var.
4. `grep -r "process.env" src/` returns only `src/lib/config/env.ts` (no scattered `process.env.X` access).

**Estimated Complexity.** Low–Medium.

**AI Coding Opportunity.** High — AI implements `src/lib/config/env.ts` from the spec verbatim. Prompt: "Implement `src/lib/config/env.ts` using @t3-oss/env-nextjs. Required server vars: DATABASE_URL (url), DIRECT_URL (url), OPENAI_API_KEY (min 10), SUPABASE_URL (url), SUPABASE_SERVICE_ROLE_KEY (min 10), SUPABASE_STORAGE_BUCKET (default 'docs'). No client vars. runtimeEnv: process.env."

### Task 0.7 — Create Folder Structure

**Objective.** Materialize the layout from `technical-design.md` §14 so future phases drop files into pre-existing directories without inventing paths.

**Technical Requirements.**

Create these directories (with a `.gitkeep` in each, since git won't track empty dirs). Note `src/` from `--src-dir` in Task 0.1 — `prisma/` and `public/` stay at repo root:

```
src/
  app/                      # routes (already exists from Task 0.1)
    api/                    # route handlers
  components/
    ui/                     # shadcn primitives (created in Task 0.3)
    shared/                 # cross-cutting components (FileDropzone, etc.)
  lib/
    ai/                     # OpenAI client, chunker, prompts, generation
    parsers/                # PDF / DOCX / Markdown extractors
    randomization/          # Fisher-Yates utilities
    services/               # documents, quizzes, attempts, analytics
    db/                     # prisma singleton + repositories/
    schemas/                # zod schemas (api.ts, ai.ts, common.ts)
    storage/                # supabase server client
    config/                 # env.ts (created in Task 0.6)
    utils/                  # timestamp formatter, etc.
    errors.ts               # AppError + error codes (file, not folder)
  types/                    # shared TS types (alternative: repo root /types)
prisma/                     # schema.prisma + migrations/  (Task 0.4) — repo root
public/                     # static assets (already from Task 0.1) — repo root
```

**Folder purposes (one-line each).**

| Folder | Holds |
|---|---|
| `src/app/` | Routes (RSC + Client). Co-locate `_components/` per route. |
| `src/app/api/` | Next.js Route Handlers — thin HTTP layer, no business logic. |
| `src/components/ui/` | shadcn primitives only. Don't edit; re-add via shadcn CLI. |
| `src/components/shared/` | Reusable components used across multiple routes. |
| `src/lib/ai/` | Everything OpenAI-related. Isolated so RAG/model swap is local. |
| `src/lib/parsers/` | Format-specific text extraction. One file per mime. |
| `src/lib/randomization/` | Pure functions used by the quiz client component. |
| `src/lib/services/` | Orchestration: combines AI + DB + Storage. Imported by route handlers. |
| `src/lib/db/` | Prisma singleton + repository helpers. |
| `src/lib/schemas/` | Zod schemas — single source of truth for API + AI validation. |
| `src/lib/storage/` | Supabase server client (uses service-role key). |
| `src/lib/config/` | Env validation, runtime config. |
| `src/lib/utils/` | Tiny helpers (`formatYmdHms`, etc.). |
| `src/lib/errors.ts` | `AppError` class + `ErrorCode` union + `toResponse(err)`. |
| `prisma/` | Schema + migrations. Repo root, not under `src/`. |
| `src/types/` | Cross-module TS types not naturally owned by a single module. |

> Import alias: `@/*` resolves to `./src/*` (set by `--src-dir` in Task 0.1). So `@/lib/db/prisma` → `./src/lib/db/prisma.ts`.

**Dependencies.** Task 0.1.

**Acceptance Criteria.**
- All directories exist (under `src/` for code, repo root for `prisma/` and `public/`) and are tracked by git.
- A new file dropped in `src/lib/foo/bar.ts` is auto-resolvable as `@/lib/foo/bar`.

**Validation Steps.**
1. `tree -L 3 -I node_modules` (or equivalent) matches the layout above.
2. `git status` shows `.gitkeep` files staged.

**Estimated Complexity.** Low.

**AI Coding Opportunity.** Medium — AI can generate the directory tree + `.gitkeep` files in one shell snippet. Prompt: "Generate a single bash command that creates the following directories under the current working dir, each with a `.gitkeep`: …"

## 5. Recommended Git Commit Strategy

### Naming convention

```
<type>(<phase>): <short imperative>
```

- `type`: `chore`, `feat`, `fix`, `refactor`, `docs`.
- `phase`: `0` for Phase 0 commits.
- Short imperative sentence, no period.

### Frequency

- **One commit per task.** 10 tasks → 10 commits is fine.
- If a task takes more than 30 min, mid-commit a WIP: `chore(0): wip — ...`.
- Push to feature branch after every commit so AI assistants pulling from the branch see fresh state.

### Examples

```
chore(0): scaffold Next.js 15 with TS + Tailwind + ESLint
chore(0): init shadcn and add 10 base primitives
chore(0): install Prisma + add singleton client
chore(0): provision Supabase + create docs bucket
feat(0): add lib/config/env.ts with Zod-validated env vars
chore(0): create lib/* folder structure with .gitkeep
chore(0): add .prettierrc + .editorconfig + format script
feat(0): root layout, app shell, sonner toaster
chore(0): smoke-check passes — phase 0 done
```

### Branching

- Single feature branch `feat/0-project-setup` for all 10 tasks.
- One PR titled `Phase 0: Project Setup` when 0.10 passes.
- Squash-merge to `main`.

## 6. Common Setup Pitfalls

### Prisma

| Pitfall | Mitigation |
|---|---|
| `DATABASE_URL` set to direct (port 5432) — runtime hits connection limit on Vercel | Always pooled URL (port 6543) with `?pgbouncer=true&connection_limit=1`. Use `DIRECT_URL` only for `prisma migrate`. |
| Prisma client not regenerating after schema change | `pnpm prisma generate` on every schema edit. Add to `package.json` `"build": "prisma generate && next build"`. |
| `Module not found: @prisma/client` after install | Run `pnpm prisma generate` once after install. The client is generated, not pre-built. |
| Hot-reload spawns hundreds of DB connections in dev | Use the singleton with `globalThis` cache (Task 0.4). |

### Supabase

| Pitfall | Mitigation |
|---|---|
| Wrong key used (anon instead of service-role) | Service-role key only, server-side. Verify you copied from "service_role", not "anon". |
| Bucket created public by accident | Re-create as private; or set policy via Supabase Studio. We never expose Storage to the browser. |
| Region far from Vercel function region | Pick `us-east-1` (Supabase) + `iad1` (Vercel) for low latency. |
| Free-tier connection limits hit during local dev with multiple terminals | Use the pooler. Restart `pnpm dev` if the dev server hangs on first DB query. |

### Next.js App Router

| Pitfall | Mitigation |
|---|---|
| `'use client'` accidentally in `layout.tsx` | Layouts should be RSC unless absolutely needed. `<Toaster />` is a client component but can be mounted from an RSC layout — works via boundary. |
| Importing server-only env into a client component | The `env` object is server-only. If a client component needs a public value, expose explicitly via prop, not direct import. |
| Route segment file naming wrong (`Page.tsx` instead of `page.tsx`) | Lowercase `page.tsx`, `layout.tsx`, `loading.tsx`, `error.tsx`. App Router is case-sensitive on naming. |
| Confusing `src/app/api/` path for `pages/api/` | We're 100% App Router. `src/app/api/<route>/route.ts` exports `GET`, `POST`, etc. |

### Tailwind

| Pitfall | Mitigation |
|---|---|
| Class doesn't apply | Check `tailwind.config.ts` `content` glob covers the file. A new top-level folder may not be matched. |
| Dynamic class names purged | Use the safelist or build the full class name as a string. Don't write `bg-${color}-500`. |
| Conflicting CSS resets | shadcn ships its own resets via `@layer base`. Don't add a separate reset. |

### shadcn/ui

| Pitfall | Mitigation |
|---|---|
| `npx shadcn add <thing>` fails with "components.json not found" | Run from repo root, the same dir where `components.json` is. |
| Re-running `add` overwrites local edits | Don't manually edit files in `components/ui/`. If you need a custom variant, wrap or extend in `components/shared/`. |
| Toast component called something else | The shadcn name is `sonner` (not `toast`). Mount `<Toaster />` from `@/components/ui/sonner`. |
| Theme tokens missing in `globals.css` | shadcn `init` should add them. If not, re-run `init` and accept overwrite for `globals.css`. |

## 7. Definition of Done

Phase 0 is complete when **all** of the following are true:

### Code

- [ ] All 10 tasks (0.1 → 0.10) committed and pushed.
- [ ] `pnpm install && pnpm dev` boots cleanly on a teammate's machine after a fresh clone.
- [ ] `pnpm tsc --noEmit` exits 0.
- [ ] `pnpm lint` exits 0.
- [ ] `pnpm prisma generate` exits 0.
- [ ] Removing any one env var from `.env.local` causes boot to fail with a clear Zod error.

### Layout

- [ ] Root URL renders the app shell (header + welcome + Get Started button).
- [ ] Sonner toaster is mounted.
- [ ] Page works on 375px mobile viewport.

### Integrations reachable

- [ ] Supabase project provisioned.
- [ ] Bucket `docs` exists and is private.
- [ ] OpenAI API key is set (existence verified, not yet exercised).
- [ ] `prisma.$queryRaw\`SELECT 1\`` returns from a one-off script.

### Repository hygiene

- [ ] `.env.local` is git-ignored and not in any commit.
- [ ] `.gitkeep` files are in every empty folder from `src/lib/*`.
- [ ] Folder structure matches `technical-design.md` §14.
- [ ] All Phase 0 commits prefix with `chore(0):` / `feat(0):`.

- ❌ Do not write the real Prisma schema — that's Phase 1.
- ❌ Do not implement upload — that's Phase 2.

- ❌ Do not configure CI workflows. (Reverted in implementation-plan v1.1; not part of this MVP.)

When everything above is true, move to **Phase 1 — Database & Infrastructure**.
